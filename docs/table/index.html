Executive Summary

Short Note: How the HTML Process Works

In traditional frontend development, rendering an HTML table from dynamic data requires manual <tr> and <td> loops, repetitive string concatenation, or hazardous innerHTML assignments.

json-renderers abstracts this entirely into a clean, 4-stage pipeline:

1. Business JSON

You pass an array of raw JavaScript objects (from API or static file) and chosen columns.

2. Runtime Call

render({...}) acts as orchestrator and initiates the transformation.

3. Spec to DOM

json-to-tag transforms the JSON schema into native browser table elements.

4. DOM Mount

The browser mounts the live table directly into your target container with zero reload.

💡 Key Takeaway: You never write loop code. The library converts your data specification into an abstract syntax tree and converts that tree into true HTML nodes using standard DOM APIs.

Deep Dive

The 4 Process Stages of HTML Table Generation

What happens behind the scenes from the moment you call render to when pixels draw on screen.

1 Input Phase

Raw Business Data

Your application supplies data as plain JSON records: 

[
  { "itemName": "Steel Wire", "baseUnit": "kgs" },
  { "itemName": "Alloy Rod", "baseUnit": "pcs" }
]
Input Data →
2 Invocation

Runtime Orchestration

You invoke the renderer with column definitions and container id: 

render({
  type: "table",
  data: data,
  columns: ["itemName", "baseUnit"],
  targetHtmlId: "dom-container"
});
Orchestrator →
3 Schema to Tag

Blueprint to DOM Nodes

json-renderers-build creates an AST spec, and json-to-tag instantiates real browser nodes:

<table class="table">
  <thead><tr><th>...</th></tr></thead>
  <tbody><tr><td>...</td></tr></tbody>
</table>
Native DOM Creation →
4 Mounting

Container Mounted

The engine safely appends the generated table into the host DOM element: 

<div id="dom-container">
  <!-- Cleanly mounted table -->
  <table ...>...</table>
</div>
